## Blocking finding: aliased console descriptors have independent admission histories

`plugins/engineering/scripts/delivery.py:155-158` indexes `_CONSOLE` by the Boolean `err`, then writes to the selected stdout/stderr buffer. `_call` at lines 255-258 gives API diagnostics the stderr entry. This correctly shares API and controller stderr history, but never establishes whether stdout and stderr are distinct physical destinations. `stackos/artifacts/checked_output.py:195-213` retains history, lock and poisoned state only inside each independent `CheckedStream` instance.

Ordinary `2>&1` redirects both descriptors to the same stream. A static counterexample using these actual adapters is an inherited protected value `left\nright`, `_echo("left")`, then `_echo("right", err=True)`. Each payload and each separate history passes: the first contains `left\n`, the second `right\n`. The physical stream contains `left\nright\n`, disclosing the protected value. No arbitrary downstream transformation is required. This is a reasoned counterexample, not an executed test.

The same split ownership permits stderr to append after a partial/uncertain stdout write has poisoned only the stdout owner. That defeats the intended no-fallback-after-uncertain-write property when the descriptors alias.

The candidate documentation's exclusion for downstream combinations of separate files does not resolve this case: these are two writers to one stream during controller execution. The requirements explicitly require shared-stream framing assessment. The owner must resolve/reuse admission history, serialization and failure state for aliases, or hold before the affected output where ownership genuinely cannot be established. Normal supported terminal/redirection cases need usable handling. A corrected candidate requires fresh independent review before tests.
