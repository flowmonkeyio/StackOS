Quick answer

What is AI workflow automation?

AI workflow automation combines a reusable workflow contract with a concrete run plan for the current request. The workflow defines the operating boundary; the run records state, dependencies, scoped tools, outputs, recovery, and verification.

Website SEO Analysis

A reviewed report with a list of pages checked, evidence for each finding, and recommended fixes in priority order. It explains missing data and coverage limits without changing the website.

Before you start

  • A reachable website URL and the business problem you want the analysis to help with
  • If relevant, priority pages or sections, target markets and anything the agent must leave outside the review
  • Optional Search Console, analytics or research access, approved exports and a reporting period; public pages can support a useful analysis when those sources are unavailable
Steps and decisions

What the agent does

  1. Confirm the website, business goal, sections to inspect and reporting period. Choose representative pages and record what is outside the review.
  2. Inspect pages, navigation, links, metadata, robots rules and sitemaps. Add connected search or analytics data when available; otherwise work from the public site and record the gaps.
  3. Have the findings independently reviewed, resolve unsupported claims, and prioritize fixes by likely value, confidence and effort. Include dependencies and a way to check each fix.
  4. Save the report, list of inspected pages and supporting evidence so someone can check the conclusions and assign follow-up work.

What you provide or decide

  • Example request: “Use Website SEO Analysis on [website URL]. Focus on our service pages and guides for UK small businesses. Check navigation, page content and indexing signals. Return findings with evidence, priorities and ways to verify a fix.”
  • Name the business goal, important sections, target markets and anything outside the review. Add a reporting period if you want search or analytics data included.
  • Connect available tools or supply approved exports. The agent can start from the public site and record the missing data. Review the findings before assigning fixes.

SEO Content Refresh

A reviewed page-edit plan, verified changes when authorized, or a later performance check. Each change keeps its source, review and verification record.

Before you start

  • Existing page URLs and the reader or business problem to solve
  • Current page content and available search or analytics evidence, from connected tools or approved exports
  • To apply changes: an accepted edit plan, permission and a supported editing route. To assess changes: the earlier record, baseline and a comparable later data window.
Steps and decisions

What the agent does

  1. Confirm the pages, business goal and whether the job is to prepare edits, apply them or assess an earlier refresh. Review existing content and comparable search data.
  2. Find the reader or technical problem before proposing exact page and link edits. Have the proposal independently reviewed and resolve the findings before applying it.
  3. Apply only authorized changes, check each result, and keep records of completed, failed or uncertain edits. Inspect an uncertain result before retrying. Preparation stops with the reviewed plan.
  4. When assessing an earlier refresh, compare later data with the saved baseline and explain the measurement limits. Record inconclusive results when the data cannot support a conclusion, and leave the content unchanged.

What you provide or decide

  • Example request: “Use SEO Content Refresh on [page URLs]. Readers should be able to try each method. Keep the URLs and useful links. Show the proposed edits and checks before changing the site.”
  • Choose the job: prepare a plan, apply reviewed edits, or assess an earlier refresh. Preparation is the default; applying changes needs permission and a usable editing route.
  • Provide current page content, the reader or business goal, and available search or analytics evidence. For an assessment, include the earlier change record and baseline.
  • Check the actual edits and the later performance result separately. A page can be successfully updated while its search impact is still unknown.

Engineering Tracked Delivery

A change checked against the original request, with test results, independent review and a recorded release status. The record shows what was completed and what still needs attention.

Before you start

  • Repository instructions and source access
  • A desired outcome and acceptance boundary
  • Authority for the requested file or system changes
Steps and decisions

What the agent does

  1. Clarify the request, affected users and systems, constraints, and what will count as a successful result.
  2. Inspect the existing code, choose an approach and checks, then plan tasks in dependency order. Review the plan before implementation.
  3. Implement authorized tasks, running independent work in parallel when useful. Test and independently review each result before starting dependent work, then check that the pieces work together.
  4. Compare the finished change with the original request, record test and review results, and state whether it was released or what remains. Close the work only when the evidence supports that status.

What you provide or decide

  • Describe the desired outcome, constraints, and authority boundary.
  • Review material design choices or production-risk gates.
  • Inspect verification, review findings, and residual risk before release.
