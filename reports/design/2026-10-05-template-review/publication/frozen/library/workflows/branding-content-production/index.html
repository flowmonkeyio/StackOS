The problem

Useful operating experience often gets flattened into generic content or a disguised product pitch.

AI can connect interviews, project evidence, prior positions, drafting, independent review, and bounded execution while keeping the operator's judgment visible.

What you do

  1. Name the topic, audience, useful lesson, and how prominently the product should appear.
  2. Share source boundaries or answer a short interview when the missing experience matters.
  3. Set packet-only, stage, or publish intent and name the target channels when execution is wanted.
  4. Answer a focused question only when missing context would materially change the piece or destination.

What the agent does

  1. Load the brand foundation, prior positions, cleared sources, and channel rules.
  2. Decide whether the optional interview is required, useful, or unnecessary; record why when it is skipped.
  3. Research and draft from traceable evidence, then run claim, voice, and sanitization review.
  4. Finalize the packet, then stop, stage, or publish according to publication_intent without adding another human checkpoint.

When this workflow helps

A reusable method, adapted to the request.

  • A solo operator wants one workflow to interview them, research the facts, pull supporting artifacts, shape the idea, draft, review, generate optional images, and publish or stage selected channels.
  • The user says they want to generate content on a topic, with evidence or source material, using the branding workflow.
  • The output should include a canonical draft plus X, LinkedIn, website, or email publication without requiring separate workflow runs.
  • Website or channel imagery may be needed, but generation should happen only after an explicit image plan.

Before it starts

Project setup required

  • An active brand voice profile or representative writing samples
  • A topic, audience, useful lesson, and product-mention boundary
  • Approved source and disclosure boundaries
  • Channel targets only when publication is in scope

What proves it worked

Evidence, not a success claim.

  • Claims-to-evidence map
  • Independent claim, voice, and sanitization verdicts
  • Durable final content-piece ref
  • Explicit packet-only, stage, or publish intent
  • Publication receipts only for selected channels

Workflow path

The reusable stages of the work.

A real run expands these stages around the request, context, selected tools, approvals, and dependencies.

10 ordered workflow stages
  1. 01

    Interview Capture

    Decide whether first-hand operator context is needed, then ask only the useful journalist-style questions or record why the interview can be skipped.

    Passes to next stage
  2. 02

    Research And Fact Collection

    Use the operator intent, interview decision, any interview pack, and cleared sources to collect and organize facts before angle selection.

    Passes to next stage
  3. 03

    Angle And Structure

    Propose one to three piece ideas, select the structure, name target channels, and decide whether images are needed.

    Passes to next stage
  4. 04

    Draft Canonical

    Write the canonical piece in the adapted operator voice from the selected angle and evidence pack.

    Passes to next stage
  5. 05

    Editorial Review

    Run one compact review pass for factual support, prior-position consistency, voice, and channel form.

    Passes to next stage
  6. 06

    Sanitization Review

    Apply disclosure policy separately and fail closed on public-use risk.

    Passes to next stage
  7. 07

    Produce Optional Images

    Resolve the selected image set, generating assets only when the image plan requires provider-generated website or channel media.

    Passes to next stage
  8. 08

    Render Channel Publication Jobs

    Produce executable website, X, LinkedIn, and optional email publication payloads plus one channel-ready publication bundle from the canonical draft and…

    Passes to next stage
  9. 09

    Finalize Content And Record

    Finalize the reviewed canonical packet and durable memory, then prepare only the publication jobs permitted by publication_intent.

    Passes to next stage
  10. 10

    Execute Publication

    Publish or stage only the jobs selected by publication_intent and target_channels, then record distribution results.

    Verified outcome

Safe stopping and recovery

Useful even when the whole path cannot run.

  • Stop after a review-ready content packet when publication_intent is packet_only.
  • After the intent-specific terminal condition is met, return closeout without creating unrelated follow-up work or changing another workflow.
  • If the voice or source boundary is missing, pause for brand-foundation setup.
  • If evidence conflicts, expose the conflict and ask one bounded decision question.
  • If publication fails, preserve the final packet and record the channel-specific blocker.
