SEO Content Refresh

The problem

Content refreshes turn into broad rewrites when search intent, current performance, technical issues, and conversion purpose are not diagnosed first.

AI can compare search evidence, page structure, project context, and editorial constraints while keeping the final judgment and publication boundary explicit.

What you do

  1. Example request: “Use SEO Content Refresh on [page URLs]. Readers should be able to try each method. Keep the URLs and useful links. Show the proposed edits and checks before changing the site.”
  2. Choose the job: prepare a plan, apply reviewed edits, or assess an earlier refresh. Preparation is the default; applying changes needs permission and a usable editing route.
  3. Provide current page content, the reader or business goal, and available search or analytics evidence. For an assessment, include the earlier change record and baseline.
  4. Check the actual edits and the later performance result separately. A page can be successfully updated while its search impact is still unknown.

What the agent does

  1. Confirm the pages, business goal and whether the job is to prepare edits, apply them or assess an earlier refresh. Review existing content and comparable search data.
  2. Find the reader or technical problem before proposing exact page and link edits. Have the proposal independently reviewed and resolve the findings before applying it.
  3. Apply only authorized changes, check each result, and keep records of completed, failed or uncertain edits. Inspect an uncertain result before retrying. Preparation stops with the reviewed plan.
  4. When assessing an earlier refresh, compare later data with the saved baseline and explain the measurement limits. Record inconclusive results when the data cannot support a conclusion, and leave the content unchanged.

When this workflow helps

A reusable method, adapted to the request.

  • Existing pages or their internal connections need bounded evidence-led improvement.
  • A prior refresh needs outcome assessment without reapplying changes.

Before it starts

Depends on the selected path

  • Existing page URLs and the reader or business problem to solve
  • Current page content and available search or analytics evidence, from connected tools or approved exports
  • To apply changes: an accepted edit plan, permission and a supported editing route. To assess changes: the earlier record, baseline and a comparable later data window.

What proves it worked

Evidence, not a success claim.

  • A reviewed proposal with the exact old and new wording, the reason for each edit, useful links to preserve and the checks to run.
  • Illustrative edit: a workflow guide says “write clear requirements” but gives no usable brief. Add the task, inputs, acceptance checks and a saved handoff while preserving the page's purpose and URL.
  • For applied work, a record of each completed, failed or uncertain edit and a check of the actual page. A successful build alone does not establish what readers can see.
  • A separate performance assessment using the saved baseline and a comparable later window. If the sample is too small or the data incomplete, the result stays pending or inconclusive.
  • One saved refresh record that connects the proposal, review, actual changes, verification and next measurement step.

Safe stopping and recovery

Useful even when the whole path cannot run.

  • Prepare closes with the reviewed exact proposal and explicit next_mode apply implementation prerequisite; no implementation means no scheduled outcome assessment.
  • Apply closes with verified or explicit partial implementation and outcome pending when no valid later window exists.
  • Assess closes with observed or inconclusive outcome and never reapplies changes.
  • Preserve applied and unknown change receipts; inspect actual current state before retrying an uncertain action.
  • If inputs, authorization or destination checks are missing, retain a prepared/blocked packet and exact repair steps.
  • Resume delayed measurement from the prior refresh ref in assess mode, preserving original implementation evidence.
  • If no changes are confirmed applied, route follow-up to apply or a blocked implementation handoff; schedule assess only after actual implementation exists.
